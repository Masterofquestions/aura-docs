Aura uses Server-Sent Events for ordered one-way updates. WebSockets are not
part of the public contract. A stream is an acceleration layer over durable
state: REST snapshots and indexed chain state remain the recovery boundary.

The opaque `rt2` cursor is a vector across the sources active in this API
deployment: `main` (indexed account/earnings projections), `sequencer`
(orders, matches and settlement), and `wallet` (private custody/funding). Read
the active subset from `GET /v1/protocol/config`; never assume a cursor contains
only one source.

## Topics

Read the live topic grammar from `GET /v1/protocol/config`. Schema version 2
currently includes patterns such as:

| Visibility | Topic pattern | Purpose |
| --- | --- | --- |
| Public | `market:{marketId}:book` | Immediate versioned book updates |
| Public | `market:{marketId}:trades` | Trade lifecycle updates |
| Public | `market:{marketId}:lifecycle` | Trading, resolution and settlement state |
| Public | `markets:all`, `trades:all`, `book-ticker:all` | Bounded global feeds |
| Private | `user:{address}:orders` | The user's order lifecycle |
| Private | `user:{address}:funding` | Deposit/funding state |
| Private | `user:{address}:settlements` | Provisional and final settlement state |
| Private | `user:{address}:account` | Holds, balances and account-version changes |

Private topics require the matching wallet session. If a developer key is also
present, it needs `realtime:public` and `account:read` as applicable. A key by
itself cannot subscribe to user topics.

## Replay capability contract

`GET /v1/protocol/config` publishes the replay contract without embedding a
transient head cursor:

| Field | Meaning |
| --- | --- |
| `cursorFormat` | Always `rt2_source_vector` for schema version 2. |
| `sources` | Active `main`, `sequencer`, and/or `wallet` adapters. |
| `minimumReplayRetentionMs` | Minimum age window retained by every active source. |
| `minimumRetainedEvents` | Minimum event-count floor retained by every active source. |
| `maximumReplayEvents` | Maximum events returned in one bounded replay. |

These are minimum service guarantees, not a promise that an arbitrary old
cursor remains replayable. Obtain an exact resume cursor from a REST snapshot
or an SSE `id:` line. Do not poll protocol configuration for a stream head.

## Use fetch-based SSE

Native `EventSource` cannot attach an `Authorization` or developer-key header.
The builder SDK uses fetch and keeps credentials out of the URL:

```ts
let account = await aura.account.realtimeSnapshot(address)

await aura.realtime.subscribe({
  topics: [`user:${address}:orders`, `user:${address}:account`],
  cursor: account.streamCursor,
  onEvent: async (event) => {
    account = await persistAndApply(account, event)
  },
  onReset: async () => {
    account = await aura.account.realtimeSnapshot(address)
    return account.streamCursor
  },
})
```

For public-only command-line inspection:

```bash
curl -N \
  'https://api.aura.markets/v1/realtime/stream?schemaVersion=2&topics=market:MARKET_ID:book'
```

Topic names may be in the query string. Credentials, session tokens and API
secrets must not be.

## Snapshot, then resume

<Steps>
  <Step title="Fetch an authoritative snapshot">
    Use `/v1/realtime/book/{marketId}/snapshot` for a book or
    `/v1/realtime/account/{address}/snapshot` for the authenticated account.
  </Step>
  <Step title="Install the snapshot atomically">
    Keep its `bookVersion` or `accountVersion` and `streamCursor` with the state.
  </Step>
  <Step title="Connect after the snapshot cursor">
    Send the cursor in the `Last-Event-ID` request header. The durable journal
    replays events committed during the snapshot request, so there is no
    subscribe gap.
  </Step>
  <Step title="Apply, then checkpoint">
    Apply and persist an event before advancing its resume cursor. Delivery is
    at least once, so deduplicate by the semantic envelope's stable `id`.
  </Step>
</Steps>

## Schema version 2 envelope

```json
{
  "schemaVersion": 2,
  "id": "sequencer:generation-1:184392:0",
  "type": "order.accepted",
  "occurredAt": "2026-08-10T20:00:00.000Z",
  "stream": "market:abc123:book",
  "streams": [
    { "stream": "market:abc123:book", "sequence": "991" },
    { "stream": "user:3Cef...:orders", "sequence": "44" }
  ],
  "source": {
    "name": "sequencer",
    "generation": "generation-1",
    "sequence": "184392",
    "ordinal": 0,
    "hash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  },
  "cursor": "rt2....",
  "bookVersion": "981",
  "data": {
    "quantityBaseUnits": "1000000000000000000"
  }
}
```

The SSE `id:` line is the opaque `rt2` source-vector cursor. The JSON `id` is
the durable event identity used for deduplication. Numeric protocol values in
`data` are decimal strings, never JSON numbers.

## Private wallet and account events

The wallet source emits only owner-sanitized state. It never includes unsigned
transactions, signatures, grants, destination secrets, raw failure text, or
custody bytes.

| Event type | Important `data` fields |
| --- | --- |
| `deposit.required` | `operationId`, `kind: jit_deposit`, `state: signing`, `amountBaseUnits`, `intentHash`, nullable `transactionId`/`failureCode` |
| `deposit.pending` | Same identity and amount fields with `state: submitted` |
| `deposit.confirmed` | Same fields with `state: confirmed` |
| `deposit.failed` | Same fields with `state: failed` and a sanitized `failureCode` |
| `withdrawal.pending` | `operationId`, `kind: withdrawal`, `state`, ordered `operationIndex`/`operationSize`, `transactionId`, `attoAlphOutflow`, `tokenOutflows` |
| `withdrawal.confirmed` / `withdrawal.failed` | The same persisted operation identity and amounts with terminal state |
| `custody.transaction_changed` | A non-final `group_funding` or `sweep` vector member; never interpret it as a completed withdrawal |
| `spendable_balance.changed` | A reason and operation ID plus `requiresSnapshotRefresh: true`; reload the account/funding snapshot rather than calculating spendable from the delta alone |

The main projection emits these authenticated-account corrections:

| Event type | Meaning |
| --- | --- |
| `position.changed` | Insert/update/delete of one YES/NO position with exact shares, cost, payout and lock fields. |
| `claimable_balance.changed` | Exact collateral base-unit totals for eligible (`claimableWinningsBaseUnits`), submitted/processing (`pendingClaimsBaseUnits`), and confirmed (`confirmedWinningsBaseUnits`) winnings. The three buckets are disjoint; never add a claim to two buckets. |
| `reward.changed` | Liquidity-maker, referral-fee, or dispute-vote reward state with an explicit kind and unit. |
| `payout.changed` | Payout queue or liquidity-reward lifecycle, including only sanitized transaction identifiers. |

Use `isRealtimeEventType(event, 'claimable_balance.changed')` from the builder
SDK to narrow `data` to the documented exact payload. Events remain at least
once, so the stable envelope `id` is still the deduplication key.

## Reset means replace state

Aura emits `event: aura-reset` when the requested cursor is no longer replayable,
a source generation changed, a replay limit was exceeded, or a restored source
diverged.

```json
{
  "schemaVersion": 2,
  "type": "replay.reset",
  "reason": "retention-exceeded",
  "requestedCursor": "rt2....",
  "currentCursor": "rt2....",
  "sources": ["sequencer"],
  "occurredAt": "2026-08-10T20:01:00.000Z"
}
```

Do not continue applying events to old state and do not merely adopt
`currentCursor`. Fetch and install a fresh snapshot, then reconnect after that
snapshot's cursor. Without an `onReset` handler, `@aura/builder-sdk` throws
instead of silently risking stale state.

## Stream errors and reconnect

`event: aura-error` carries a stable code, request ID, `recoverable` flag and
last safe cursor. Handle the complete code set:

| Code | Required response |
| --- | --- |
| `slow_consumer` | Reduce synchronous callback work, then resume after `lastCursor`. |
| `replay_unavailable` | Keep the last durable snapshot/cursor and retry with bounded backoff. |
| `session_expired`, `session_revoked` | Obtain a new wallet session before reconnecting a private stream. |
| `session_revalidation_unavailable` | Keep private state frozen and retry only after session validation recovers. |
| `developer_key_revoked`, `developer_key_expired` | Stop using the key and reconnect with an active replacement. |
| `developer_key_rotated`, `developer_key_generation_changed` | Reload the current key generation from the secret manager before reconnecting. |
| `developer_key_scope_changed` | Reconnect only with a key that still grants every requested stream scope. |
| `developer_key_revalidation_unavailable` | Keep state frozen and retry with backoff after key validation recovers. |
| `source_unavailable` | Preserve the last snapshot/cursor and retry after the advertised source recovers. |

Treat `recoverable` as authoritative. A recoverable frame permits a later
reconnect; it does not mean retry immediately or continue applying stale state.
The SDK passes every typed frame to `onStreamError`, retains `lastCursor`, and
uses bounded backoff.

- Reconnect with bounded exponential backoff and jitter.
- On `slow_consumer`, reduce work in the callback or move persistence off the
  read loop before resuming.
- Never downgrade a failed private subscription to a public one while leaving
  private account state on screen.
- Treat malformed frames, incompatible schema versions, cursor divergence and
  numeric money fields as protocol errors, not ignorable warnings.
- Expect duplicates across reconnects and deployments.

The service also enforces per-IP, per-session and per-developer-key connection
limits. A `429` includes rate-limit headers; do not reconnect in a tight loop.

## Book and settlement correctness

An immediate public book is suitable for execution. A separate aged qualified
book may be used for pricing/reward calculations; do not conflate the two.

A match can be provisional before funding and Clearinghouse settlement. Handle
`settled`, `unwound`, `funding-failed` and reorg/recovery corrections. Final
volume, earnings and P&L analytics use settled state only.
