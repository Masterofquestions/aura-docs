Build on Aura. Market data is public and needs no key, and everything a user can
do in the app is available over the same API.

## Make your first request

<CodeGroup>
```bash cURL
curl -s "https://api.aura.markets/v1/markets?limit=5&status=open"
```

```javascript JavaScript
const { markets } = await fetch(
  'https://api.aura.markets/v1/markets?limit=5&status=open'
).then((r) => r.json())

for (const m of markets) console.log(m.question, m.bestBidYes)
```

```python Python
import requests

res = requests.get(
    "https://api.aura.markets/v1/markets",
    params={"limit": 5, "status": "open"},
)

for m in res.json()["markets"]:
    print(m["question"], m["bestBidYes"])
```
</CodeGroup>

That is the whole setup. No signup, no key, no header.

## How it is shaped

- **Reads.** Markets, prices, the order book, trades, vault state, oracle and
  governance data. All public.
- **Realtime.** One SSE endpoint multiplexes live order, fill, dispute, and
  account events with lossless reconnects.
- **Writes** (`/v1/tx/*`). The API builds **unsigned** transactions for your
  client to sign with its own wallet. Aura never holds private keys, so a
  compromised API cannot move your funds. It also means you always need a local
  signer.

The endpoint reference is generated from the running service's OpenAPI 3.1 spec,
so it cannot drift from the implementation.

## Discovery

Built for integrators, not for lazy implementers:

- **Faceted lists.** Every list endpoint accepts `?facets=true` and returns
  category, tag, and status counts in the same response, so a UI can render
  filter chips without a second request.
- **Cursor pagination.** Stable across inserts and fast at depth. Offset
  paging via `?page=` is still supported for compatibility.
- **Rich filters.** `?q=`, `?category=`, `?tags=`, `?status=`, `?creator=`,
  and `?minVolume=` on `/v1/markets`. Tag matching is AND, so all listed tags
  must be present.
- **Sortable.** `?sort=created-at|volume|best-bid-yes|recently-traded` with
  `?order=asc|desc`. Use `/v1/trending` for the composite-score sort.
- **Field projection.** `?fields=id,question,bestBidYes` trims the wire
  weight for thin clients.
- **Unified search.** `/v1/search?q=` runs a strict tsquery first with a
  fuzzy trigram fallback when nothing matches. The result type is a
  discriminated union, so adding events or users later is non-breaking.
- **Transparent trending.** `/v1/trending` returns the full algorithm and
  per-market component scores so the ranking is auditable.
- **Categories and tags as first-class.** `/v1/categories` and `/v1/tags`
  enumerate the taxonomy with market counts.

## OpenAPI spec

The machine-readable spec is published at
[`/openapi.json`](https://api.aura.markets/openapi.json) on the live API and
is generated directly from the Fastify + zod route definitions, so it can
never drift from the implementation.
