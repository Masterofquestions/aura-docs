Choose credentials and delivery mechanisms by capability, not convenience.

| Integration | Developer key | User session | Restricted trading authorization |
| --- | --- | --- | --- |
| Public market-data page | Optional | No | No |
| Server-side public feed or webhook | Yes | No | No |
| Private portfolio/account view | Yes for builder quota | **Matching user** | No |
| Place BUY/SELL orders | **`trade:place`** | No on the order request | **Matching user, capped** |
| Cancel or run a dead-man switch | **`trade:cancel`** | No on the order request | **Matching user, capped** |

A developer key never signs and never gives access to another user's private
events. Do not build a service that asks users for wallet seeds or raw private
keys; Aura intentionally has no raw seed export.

## Bootstrap from canonical state

1. Fetch `GET /v1/protocol/config` and verify the environment.
2. Fetch the relevant REST snapshot.
3. Connect to schema-v2 SSE after the snapshot's `streamCursor`.
4. Apply events idempotently by durable event ID.
5. On a reset, replace state from a new snapshot.

Do not hard-code collateral decimals, fees, contract addresses, topic patterns,
batch limits or intent lifetimes. Configuration changes carry an ETag and a
`configVersion`.

## Public book versus qualified pricing state

The public execution book updates immediately. Aura may also maintain a
time-qualified view for pricing and liquidity rewards. Use the immediate book
for quoting/trading and the qualified feed only for the purpose documented by
that endpoint. A 30-second qualification delay is not a reason to add stale
polling to execution surfaces.

## Quote before acting

`POST /v1/markets/{address}/quote` supports BUY and SELL and shares the real
matcher, fee and rounding implementation. Inspect:

- quote and expiry time;
- book version and stream cursor;
- partial/unfilled amount;
- average and worst execution ticks;
- exact fee and collateral base units;
- spendable state when a wallet session is present;
- every warning.

Quotes are simulations, not reservations.

## Private account composition

`GET /v1/users/{address}/account` combines sequencer, wallet/node and indexed
state with explicit provenance. The path address must match the session. Never
add raw balance, pending deposit and spendable balance together; the response
already avoids double counting holds and obligations.

Large order and position collections are truncated with cursor-paginated
continuations. Keep the snapshot cursor so private SSE can safely catch up.

## Provisional execution and final analytics

An accepted/matched order is not automatically a settled fill. Funding can
fail, a match can unwind, and chain settlement can reorg or recover. Keep those
states visible. Use settled records only for final volume, P&L, creator fees,
referral earnings and builder attribution analytics.

Detached `builderCode` attribution is attribution-only at launch. It does not
change fee or reward economics. Do not promise revenue share based on it.

## Webhooks

Webhooks are durable, ordered per endpoint and delivered at least once.

- Verify HMAC against the exact raw body before parsing.
- Reject timestamps outside the replay tolerance.
- Deduplicate on `x-aura-webhook-id` with a database unique constraint.
- Return success for an already-consumed event ID.
- Echo the signed verification challenge header for endpoint activation.
- Keep the one-time secret in a server-side secret manager and rotate it.
- Inspect attempts and manually replay only after the handler is fixed.

Private topics need a live authorization from the matching user. The user can
revoke private webhook access without the builder's developer key.

## Idempotent writes and partial success

Provide a fresh, stable `idempotency-key` for each logical write and reuse it
only when retrying that same operation. If a one-time developer or webhook
secret was lost after a successful request, Aura cannot recover it; rotate the
created credential instead.

Batch cancellation is non-atomic. Read every per-order result. A fill and a
cancel may race, so a mixed response is not a transport failure.

## Transaction reconciliation

After any Alephium submission, call `GET /v1/transactions/{txId}` instead of
implementing one poller per operation. Public callers see public correlations;
the matching user session reveals its private associations. `aura.sequencer`
reports the public sequencer lookup and its exact snapshot cursor. For an owned
wallet-custody transaction, `aura.walletCustody.transaction.sequencer` also
contains owner-sanitized `privateAccount.matches` and `privateAccount.cancellations`.
Absence or an unavailable lookup is not proof that a chain transaction failed;
continue using the explicit lookup/found/chain states.

## Historical data provenance

- Candles are aggregated from settled Clearinghouse fills.
- Retained book samples are raw one-minute observations with explicit gaps.
- Late indexing, reorg and settlement corrections replace affected projections.
- Aura never invents historical depth it did not retain.

## Public trading-contract gate

Use only order, authorization, cancellation and dead-man-switch operations that
appear in the published OpenAPI document and builder SDK. Do not call internal
wallet/enclave routes, and do not revive deleted on-chain CLOB build-tx routes.
