When an Aura transaction fails on-chain, Alephium reports it as a numeric
assertion failure rather than a message. This page turns that number back into
the thing that actually went wrong.

<Note>
These are **contract** error codes, returned by transactions. If you are getting
an error back from the REST API instead, you want
[API errors](/api-reference/errors), which use string codes like
`INVALID_ARGUMENT`.
</Note>

## Reading a failed transaction

A reverted transaction reports the contract address and a numeric code:

```text
Assertion Failed in Contract @ <contract-address>, Error Code: <N>
```

Match the address and code to the artifact for the active network and release.
The same number can mean different things in different contracts. An address
outside the singleton list is not enough to identify the contract type. Shared
InstantMarket errors appear under [MarketConstants](#marketconstants).

<Note>
Aura is pre-mainnet. These tables describe the currently committed artifacts;
they do not prove a deployment. Codes have changed during pre-mainnet development:
for example, CheckpointRegistry moved from 900–902 to 940–942 on August 21, 2026.
Never decode by table position or renumber an already deployed code.
</Note>

The tables below are generated from compiler artifacts and reviewed explanations.
Update them through Aura's maintained error-code sync tool. Numeric gaps and
reserved historical slots are intentional. Codes at or above 700 share one
repository-wide namespace, checked by the generator.
